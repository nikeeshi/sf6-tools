# TASKS

info-sources の残タスクと、セッションをまたぐ引き継ぎ。仕様・方針は [README.md](README.md)。

## 前提(新しいセッションが知らないこと)

- **目的は攻略情報を効率よく取ること**と、**くそ記事に二度引っかからないこと**、**ツールに流し込める
  データの在り処を知ること**、**AI が疑問を持ったときの引き先を用意すること**。詳細は README の「目的」
- **格ゲーはコンボだけではない。** コンボの木は本人にも作れる。辛いのは**コンボしていないとき**で、
  展開が速すぎて全対応できないから**的を絞って決め打ちしている**。**そこで何を考えているか**が本命
- **攻めと受けは同じループの表と裏。** 片側だけの資料は半分。対にして置く
- **強い ≠ 有用な発信源。** 強さは実行能力であって探索能力ではない。攻略を探すのが得意で強くない人がいる
- **モダン/クラシックは情報源の選別基準にしない。** 入力の話であって攻略の話ではない
- **今やっているのは情報を取ることではなく、情報源を探すこと。** ただし**中身を見ないと質は判定できない**
  ので、判定に必要な範囲では読む
- **採用の線は「匿名はアウト、HN ありは OK」。** 実名でなくていいが、書き手が特定できること。
  `wiki.supercombo.gg`(規約)・`pachi-mea.com`・`sf6-ingrid.com`(どちらも匿名)は除外済み

### やらかしから来ている決まり(全部実際にやった失敗)

- **読まずに評価を書かない。** 見出しの構造だけ見て「採用」と書いて2回失敗した(ゴジライン・pachi-mea)
- **大会データは年で絞る。** エレナはウル4にもいるので、年を見ないと2014年の選手が混ざる
- **Liquipedia は予選・プールのページまで見る。** 本戦だけだと取りこぼす(エレナの Kosaku)
- **「Top8 にいない」は「いない」ではない。** 1大会の顔ぶれで経路を否定しない。実際に漁ってから判断する
- **規約を先に読んでから叩く。** X を直接 curl してから禁止と知った
- **取ったら数件を目視してから書き始める。** 形を確かめずにファイルを書いて、3回書き直した回がある

## 環境まわり(そのまま使える手順)

- **ネットワークは開通済み。** note・YouTube・X・Reddit・攻略ブログ・公式サイトすべて到達する
- **`streetfighter.com` は素の curl だと 403。** ブラウザの User-Agent を付ければ 200。
  ポリシーではなくサイト側の UA 判定
- **note の API**: 記事一覧 `note.com/api/v2/creators/<urlname>/contents?kind=note&page=N`、
  本文 `note.com/api/v3/notes/<key>`、ハッシュタグ `note.com/api/v3/hashtags/<tag>/notes?order=new&page=N`。
  検索 API(`/api/v3/searches`)は 403
- **Liquipedia の API**: `liquipedia.net/fighters/api.php`。**gzip 必須**(`--compressed`、
  無いと 406)。使い方と wikitext の読み方は [common.md](common.md) の大会の節
- **公式のバトル変更リスト**: `streetfighter.com/6/buckler/ja-jp/battle_change` の `__NEXT_DATA__` に
  **全30キャラ・全バージョンが入っている**。1回の取得で全部読める
- **人の発信は、中身の手前まで見られる。** 詳細は [common.md](common.md) の「この環境から人の発信を
  どこまで見られるか」
  - **X は規約でスクレイピング禁止。** `x.com/<handle>` を curl で取るのは**やらない**
    (2026-08-09 に一度やってしまった。詳細は common.md)。API は有料、Grok も課金
  - **X の投稿は Yahoo リアルタイム検索で見る。**
    `search.yahoo.co.jp/realtime/search?p=<クエリ>` の `__NEXT_DATA__` →
    `props.pageProps.pageData.timeline.entry`。1クエリ最大40件
  - **YouTube**: `youtube.com/feeds/videos.xml?channel_id=UC...` で**直近15本のタイトルと日付**が取れる。
    チャンネル ID はチャンネルページ HTML の `"externalId":"UC..."` から
  - **動画の中身は扱えない。** 映像も音声も無理で、自動字幕も 429 で取れなかった。
    動画は**「リンクのみ」の状態で記録して後回し**にする

## 動画をどうするか(未着手・大きい宿題)

**攻略情報の主体が動画に移りつつある**ので、動画が扱えないことは環境の制約であると同時に
**このプロジェクトで AI 側が担える範囲が狭まっていく**という構造的な問題でもある。案が2つ出た。

1. **字幕を取る手段を探す。** `yt-dlp` に字幕だけ取るオプション(`--write-auto-sub --skip-download`)がある。
   字幕を載せている第三者サイトもある。**watch ページが 429 を返した1回だけで「不可」と結論を書いたのは
   早すぎた。** ただし **X の件があるので、規約を先に読んでから触る**
2. **映像解析で動きを割り出す**(LLM は関係ない領域)。スト6はオンラインの試合が全部見られるので、
   リプレイを流し込んで解析するアイデア。**姿勢から技を判別するより「UI を読む」ほうが桁で簡単**
   — フレームメーター・体力/ドライブ/SAゲージ・コンボカウンター・ダメージ表示は
   **位置も色も固定**。特に**フレームメーターは1フレームごとの状態が最初から可視化されている**。
   ダメージとコンボカウンターが読めれば**レシピとダメージの対**が映像から生成でき、
   damage-calc の検証データになる
   - **`frame-meter/frame-meter-studio.html` は UI を描画する側**であって解析ではない(確認済み)
