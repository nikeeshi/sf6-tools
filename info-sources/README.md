# info-sources

スト6の攻略情報を取りに行くための、**情報源そのものの索引**。

## 目的

このリポジトリの他のプロジェクト(move-db・combo-count)は、ゲーム仕様を実測から推定し、そこからコンボを
逆算していくボトムアップの作業。info-sources は**その正反対**にある。

自分で測れば分かることは自分で測ればいい。問題は、**測っても絶対に出てこない情報**があること。

- 「この技が強い」「この連携が強い」という評価
- 実戦で機能する起き攻め・固めの組み立て
- キャラ対策(下の「攻めと受けは同じもの」を参照)
- そのキャラで何が定石として共有されているか

仕様は測定で確定できるが、**何が強いかは人が対戦を重ねて見つけたものしか存在しない**。そこを埋めるのが
このディレクトリの役目。

**用途は4つ。**

1. 攻略情報を効率よく取りに行くため。いい情報源を知っておく
2. **くそみたいな記事に二度引っかからないため。** 読んで駄目だったものを駄目だったと書き残す
3. コンボ閲覧ツールを作ったときに**流し込める形のデータ**がどこにあるか分かるように。damage-calc の
   テストデータとしても使える
4. **AI が疑問を持ったときに、どこを探せばいいか分かるように。** そのための索引が
   [common.md](common.md) の冒頭にあるルーティングテーブル

**ここは情報そのものではなく、情報の在り処を置く場所。** ただし**中身を見ないと情報源の質は判定できない**ので、
判定に必要な範囲では踏み込んで読む。

## コンボは目的の一部でしかない

**格ゲーはコンボだけではない。** コンボの木を作るのは本人にもできる作業で、本当に辛いのは**コンボしていないとき**。

対戦は展開が速く、**全部の選択肢に対応するのは人間には不可能**。だから誰でも的を絞り、情報を絞り、
ある程度は決め打ちで動いている。**そこで何を考えているか**が、いちばん取りにくくていちばん価値がある情報。

つまり欲しいのは:

- **何を捨てているか** — 全部見られない以上、必ず捨てている選択肢がある。その捨て方
- **なぜその択なのか** — 同じ状況に3つ択があるとき、なぜそれを選ぶか
- **見てから反応できないものへの事前の構え**

## 攻めと受けは同じもの

キャラ対策を「自分がどう攻略するか」と「相手にどう対策されるか」に分けても意味がない。**同じループの表と裏**。

> アレックス vs イングリッドで、イングリッドのサンシュートにアレックスがどう対応するか。
> その対応に対してイングリッドはどうするか。さらにその返しは。

どちらかに強い技や行動があって、相手がその対処をして、攻め側がその対処への対策をして、と回り続ける。
**片側だけの資料は半分**なので、攻め側の記事と受け側の記事は対にして索引に置く。

なお**範囲は広がらない**。「イングリッド対策」の記事を集めればいいので、相手キャラ29体分の情報源は要らない。

### 深さの物差し: 何周回っているか

| 周回数      | 中身                                         |
| ----------- | -------------------------------------------- |
| **0周**     | 「この技が強い」「このコンボが入る」で終わり |
| **1周**     | 相手の対応が書いてある                       |
| **2周以上** | その対応への返しまで書いてある。**本命**     |

0周は質が低いという意味ではなく**段階が違う**。最初の1周を回すための土台として要る。

## 情報源の3層 + 索引型

| 層                 | 中身                               | 性質                                                                     |
| ------------------ | ---------------------------------- | ------------------------------------------------------------------------ |
| **一次情報(公式)** | フレーム表・パッチノート・公式統計 | 正しいが「どう使うか」は書いていない。move-db が既に食っている層         |
| **集約サイト**     | 攻略ブログ・wiki・ランキング集計   | 網羅性はあるが浅く、更新が遅れる。**プレイヤーを見つける入口として優秀** |
| **プレイヤー発信** | X・YouTube・note・配信アーカイブ   | 深いが散在して腐る。**本命はここ**                                       |

**これとは別に「索引型」がある。** 自分では書かず、他人の記事や動画を集めて分類しているだけのサイト。
発信者を一気に洗い出せるので入口としては非常に強いが、**そこに書かれている中身を情報として信用しては
いけない**。実例として `sf6-ingrid.com` は自前のガイドを持っているように見えるが、数値は他人の記事と
一致する一方で技名が違っていた(サイト自身も「技名は推定を含む」と断っている)。**索引型は
「誰がいるか」を取る先であって、「何が正しいか」を取る先ではない。**

## 強いプレイヤーの逆引き経路

キャラ別に情報が集まるので、「そのキャラを使う人」を先に特定し、その人の発信先を辿るのが基本線。

1. **大会成績から** — Liquipedia の使用キャラから拾う。**実際に使える**(下記)
2. **ランクマの数字から** — 各キャラの MR 上位プレイヤーを集計している人がいる([common.md](common.md))
3. **コミュニティのハブから** — キャラ別ハッシュタグ、攻略記事が引用しているプレイヤー、リプレイ解説の題材。
   **X は規約でスクレイピング禁止なので Yahoo リアルタイム検索を経由する**([common.md](common.md))
4. **強いプレイヤーの周りから** — 配信の常連、検証を投げているリスナー、コミュニティの住人
5. **チームの非選手スタッフから** — アナリスト・ストリーマー・ユース

**経路1について。** 以前ここには「EWC 2026 の Top8 にイングリッドは0人だから大会経路は使えない」と
書いてあったが、**これは間違いだった**。1大会の Top8 だけを見て経路そのものを死んだ扱いにしていた。
実際に Liquipedia を漁ったら、イングリッドは CPT 2026 World Warrior に世界各地で出てきて、
**優勝者も複数いた**([ingrid.md](ingrid.md))。**Top8 の顔ぶれは母数ではない。実際に漁ること。**

**経路4が要る理由。** 強さは「攻略を理解し、かつ実行できる能力」であって、**探索能力とは別物**。
攻略を探すのが得意で強くない人がいる。実例として、カワノ選手の配信の常連である「白身にぃ」は
**コンボルートについてはカワノ選手より詳しい**と言われる。武器職人のように、ルートを探すことだけに
特化して遊んでいる人がいる。こういう人は経路1にも経路2にも出てこないので、**強い人の周りを見るしかない**。

**経路5が刺さる。** SFL のチームには**選手以外の役割**があり、そこに探索型が制度として存在している。
Liquipedia のチームページから役割付きで引ける([common.md](common.md))。

| 役割              | 性質                                           | 実例                             |
| ----------------- | ---------------------------------------------- | -------------------------------- |
| **Analyst**       | **分析が仕事**。探索型そのもの                 | popolinlin(Nagoya OJA)           |
| **Streamer**      | **発信が仕事**。選手枠ではない                 | ハイタニ(REJECT)、Kosaku(VARREL) |
| **Youth/Academy** | **プロの練習相手の層**。制度化されたスパー相手 | VARREL に7人、REJECT に3人ほか   |
| Coach             | 教えるのが仕事なので言語化されている見込み     | Daikoku(VARREL 助監督)           |

**popolinlin は経路2と経路5で重なった。** madaraomi のモダン名簿に MR2283(イングリッド)で載っている人が、
**Nagoya OJA のアナリスト**だった。**選手ではないので大会経路には出てこない。**
「強いが発信していない人」でも「発信量だけ多い人」でもない、探しにくい層がここにいる。

**ユース枠は「スパー相手層」の可視化。** SFL 期間中は**キャラ対策のためにスパー相手の取り合い**が起きる。
プロの仮想敵として対戦練習に付き合う層がいて、**この層も結構強い**。ユース/アカデミー枠はそれが
チームに囲われた形。ユース選手は大会にも出るので**使用キャラが引ける**
(例: Yude→春麗、Susa→ブランカ、eguto→舞、tako→キンバリー)。

## プロと配信者の線引き

**「プロ」は SFL に出ているかで一応分ける。** SFL Japan 2026 のロースターは [common.md](common.md) に置いた。

**行き来がある。**

- **元プロ → 今は配信者**: ハイタニ(REJECT に Streamer として在籍)
- **配信者 → プロ**: YAS(REJECT で SFL 出場)、なるお

**元プロの配信者は「上手さで売っている」層がある。** コーチングやコミュニティ活動をしていて、
**攻略もちゃんと続けていてプロと情報交換したりスパーしたりしている**。単なる過去の人ではない。

**ただし「配信者だから情報発信が上手い」は偽。** 配信者には
**上手さで魅せる人**と**キャラクター性・カリスマ性で魅せる人**がいて、後者から攻略は出てこない。
**配信者という属性は情報源の質の保証にならない。** 中身で判断する。

## MR と強さは別

**MR が高い ≠ スト6が強い。** 大会に出ているがランクマに重きを置いていない人がいる。

**逆向きだけが真。**

- **「強い人はやろうと思えばレジェンドに行ける」→ 真。** どぐらが全キャラでレジェンド到達に挑戦していた
  ように、上位のプレイヤーは行こうと思えば行ける
- **「レジェンドじゃないから弱い」→ 偽。** ランクマをやっていないだけの可能性がある

だから **MR 名簿(経路2)に載っていないことは、その人が弱いことの証拠にならない。**
経路2は「そこにいる人は強い」を言えるが、「いない人は弱い」は言えない。

## 採用基準

**次の2軸のどちらか一方でも満たせば採用。** 用途が違うだけで優劣ではない。

| 軸                       | 中身                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| **データとして食えるか** | 記法が一貫、レシピと数値が対になっている、機械で拾える。ツールへの流し込み・damage-calc の検証に使える |
| **「なぜ」があるか**     | 択の理由、捨てているもの、相手の対応への構え。上の周回数が1周以上                                      |

どちらも無ければ「入口」止まり。**入口も要る**(最初の1周を回す土台)ので、捨てずに段階を書いて置く。

**複数経路での名前の重複は、採用条件ではなく「実在と信用の傍証」。** 以前は重複を採用条件にしていたが、
それだと**1経路にしか存在しない探索型が原理的に全部落ちる**ので格下げした。

**強さは基準にしない。** シルバー・ゴールド帯の人の記事は深い駆け引きまで理解していない可能性があるので
その部分は鵜呑みにしない、という程度の注意にとどめる。操作が下手でも知識があれば書けるものはある。
**MR も肩書きも基準にしない**(下の「MR と強さは別」「プロと配信者の線引き」)。

**モダン/クラシックの別は情報源の選別に使わない。** モダンは入力の話であって攻略の話ではない。
モダンに無い技で重要なものはほとんど無く、攻略にそこまで差は出ない。**操作タイプは、古い情報を読むときの
読み替えレイヤーとしてだけ効く**(パッチでモダンの技配置が変わることがあるため。[common.md](common.md) の
公式の節を参照)。

## 情報源カードの項目

| 項目         | 意味                                                            |
| ------------ | --------------------------------------------------------------- |
| **発信者**   | 個人名・ハンドル。同一人物が複数媒体で出すので人を主キーにする  |
| **媒体**     | 公式 / wiki / ブログ / note / YouTube / X / 統計                |
| **扱う内容** | コンボ / セットプレイ / 立ち回り / キャラ対策 / フレーム / 統計 |
| **側**       | **攻め** / **受け**(そのキャラへの対策) — 対にして置く          |
| **型**       | **専任** / **網羅** / **索引**                                  |
| **周回数**   | 0周 / 1周 / 2周以上                                             |
| **更新性**   | 単発 / 継続                                                     |
| **確認状態** | 下記                                                            |
| **時期**     | いつ時点の情報か。パッチ差分を当てるのに要る                    |

**専任か網羅かは重要な区別。** 網羅型は抜けが少なく入口に向くが、そのキャラ固有の深い話は専任型にしかない。

## 確認状態を必ず書く

読めていないものを読んだように書かないために、状態を明示する。

| 確認状態       | 意味                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| **未読**       | タイトルとスニペットだけ。中身は見ていない                                                             |
| **リンクのみ** | 動画・配信。**この環境では映像も音声も扱えない**ので中身を判定できない。存在と発信者だけ記録して後回し |
| **既読**       | 本文を読んで内容を確認した                                                                             |
| **採用**       | 読んだうえで、継続的に見る価値があると判断した                                                         |
| **低評価**     | 読んだうえで、優先度を下げると判断した。理由を書く                                                     |
| **除外**       | 読んだうえで見ないと決めた。理由を書く                                                                 |

**「リンクのみ」を分けている理由。** プロの攻略動画は最上位の情報源になりうるが、この環境からは中身を
判定できない(自動字幕の取得も試したが取れなかった)。**判定できないものを判定したふりで書かない**ために、
未読とは別の状態にしてある。

**「低評価」を残すのが目的の2番。** 読んで薄かったという事実自体が価値のある記録なので、消さずに残す。

## 除外リスト

| サイト               | 理由                                                                                                                                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wiki.supercombo.gg` | 当たり判定・歩き速度など、**プレイからは絶対に測れないデータ**が載っている。スト6は当たり判定を可視化できないゲームなので、これらは吸い出し由来と考えられる。大会規則やゲームの規約に抵触しうるため使わない |

**この基準は他サイトにも波及する。** 当たり判定の画像や数値を載せているサイトは出どころが同じはずなので、
同じ理由で除外候補になる。見つけた時点で個別に判断して、結果をこの表に足していく。

**2026-08-09 時点で読んだ範囲(sf6-ingrid.com・かくぶろ・ドスの note・ゴジライン)には判定画像・判定の
数値は無く、除外に追加したものはない。** ドスの note は体力・前ステ・バクステ・投げの硬直差といった数値を
持っているが、**これらはプレイから測れる値**なので基準には抵触しない。

**公式のパッチノートは別扱い。** バトル変更リストには「やられ判定を後方に縮小しました」のような
判定に関する記述があるが、これはカプコン自身が文章で公表しているもので、吸い出しではない。

## 情報の鮮度とパッチ

**スト6は調整で技の使い方が根本から崩れるゲームではない。** 差分さえ押さえていれば古い情報も十分に使えるので、
情報源を「古いから」という理由だけで捨てない。各エントリに時期を書いておき、パッチ差分は別途追う。

直近の区切りは **2026-08-03(Year4 開幕)** — ヤスミン参戦、イングリッドは小幅な強化。

**ただしキャラによっては話が別。** Year4 では**舞とエドが大きく調整された**ので、この2キャラは攻略自体が
今後変わっていく。大きな調整を受けたキャラでは、**パッチ以前の情報の価値が実際に落ちる**。

**年をまたぐと話がまるで別。** 上の「古い情報も使える」は**同じ Year の中での話**。Year をまたぐと調整が
積み上がるので、**古い年の情報は意味を失う**。実例として**リリーは調整がかなり入っていて、Year1(2023年)の
情報はもう使えない**。「時期を書いておけば読める」で済むのは直近1〜2パッチまでで、**2年前の記事は
情報源として数えない**。

さらに**情報源そのものが消える方向にも効く。** 大きな調整を受けたキャラの使い手は、キャラを変えるかどうかを
悩む。発信をやめたり別キャラに移ったりするので、**「そのキャラの主要な情報源が今後も更新され続けるか」は
パッチによって変わる**。

## 言語

日本語・英語の両方を対象にする。スト6は日本のプレイヤーが強いが海外勢も活躍しており、切り捨てる理由がない。
