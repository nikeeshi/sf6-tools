# patch-notes

公式が出したパッチノート・不具合修正告知の**原文の保管場所**。要約・解釈は書かない。

技データやフレーム値の変更をこのレポジトリに反映するとき、根拠として参照する。

告知の出方が3系統あるので、置き場所も3つに分かれる。

## battle-change/ — 公式バトル変更リスト

出典: `https://www.streetfighter.com/6/buckler/ja-jp/battle_change/<id>`

大型アップデートに伴う調整。`<id>.json` の `<id>` がそのままURLの末尾になる。2023.07.24〜2026.08.03の**全21版**を取得済み。`202405` と `202506` の2版だけIDが日付でなく年月。

中身はページの `__NEXT_DATA__` にある `adjust` ノードをそのまま書き出したもの。加工していないので、本文中の改行は `<br>` のまま残っている。

| キー       | 内容                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------- |
| `title`    | 版の表示名。例: `2026.08.03 update`                                                             |
| `policy`   | 全体コンセプトとキャラ別コンセプトの文章                                                        |
| `common`   | 共通システムの変更                                                                              |
| `fighter`  | キャラ別の変更。`detail[]` が技単位で、`body[]` の要素が `category`(調整 / 不具合修正)と `text` |
| `versions` | 全版のIDと表示名。取得時点の一覧                                                                |

取得手順: ページのHTMLを取り、`__NEXT_DATA__` から `adjust` ノードを抜いてそのまま書き出す。全版のIDは、最新版ページの `adjust.versions` に一覧で入っている。既定のUser-Agentでは403で弾かれるため、ブラウザのものを送る必要がある。

## update-maintenance/ — アップデート・メンテナンスのお知らせ(抜粋)

出典: `https://www.streetfighter.com/6/buckler/ja-jp/information/detail/<slug>`

バトル変更リストに載らない修正が、この告知の本文に直接書かれていることがある。全82記事のうち、読んで残すと決めたセクションだけを `YYYYMMDD.json` に保存する。slugの `update` / `mainte` という接頭辞は付け方が揺れていて(表題が「アップデートのお知らせ」でもslugが `mainte` のことがある)分類の役に立たないので、ファイル名には使わない。**どれを残すかは人が読んで決める**もので、このディレクトリに在るファイルそのものが判断の記録になる。

取得手順: 記事本文は一覧ページ `information/update_maintenance/<ページ番号>` の `__NEXT_DATA__` に、`info_list[].body` として全文入っている。個別の記事ページを開く必要はない。

| キー      | 内容                                                     |
| --------- | -------------------------------------------------------- |
| `slug`    | 記事URLの末尾。例: `update20250704`                      |
| `url`     | 記事のURL                                                |
| `title`   | 記事の表題                                               |
| `section` | 切り出したセクションの見出し名。例: `バトル変更`         |
| `partial` | 一部だけを抜き出した場合に、その範囲を書く。全体なら無し |
| `html`    | セクションのHTML。無加工                                 |

セクション見出しは時期によって書かれ方が違う(`article_term` クラスの有無、`<strong>` の有無、色指定つき、素のテキスト、全角空白での字下げ、`<h3>` に `◆` を付けたもの)。いずれも見出しが独立行になっているので、タグを剥がして `[〜]` または `◆〜` だけの行を見出しとみなして切り出している。セクション名はどちらの書き方でも記号を除いた部分を指す。

**そのセクションが記事の最後の見出しだった場合、末尾の定型文まで含まれる。** 「その他、細かな不具合を修正しました。」「ご協力いただき、ありがとうございました。」がそれ。切り出し規則を機械的に保つため、あえて落としていない。

## 臨時修正の告知

出典: 公式X (@StreetFighterJA)

臨時メンテナンスによる修正はバトル変更リストに載らず、Xでのみ告知される。`YYYYMMDD.md`(告知の公開日)に1告知1ファイルで置く。同日に複数あれば `YYYYMMDD-2.md` と連番を振る。

先頭に出典(URL・アカウント・公開日時)を書き、本文はコードフェンスに入れて原文のまま置く。フェンスに入れるのは改行と記号をmarkdownに解釈させないため。
